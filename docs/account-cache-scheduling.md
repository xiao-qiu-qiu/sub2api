# 账号调度与缓存保持

从 `2.19.66-codeq` 起，已有会话优先复用原账号，新流量参考持续会话的短期容量预留进行分流。

## 已有会话

- 会话黏性和 `previous_response_id` 命中后，先检查原账号。加权选号、其他账号更空闲、历史首 Token 较慢、尚未达到硬上限的 RPM 余量，不再单独触发换号。
- 原账号并发已满时进入原账号队列。黏性等待上限至少为 **10 秒**；现有配置更长时继续使用原值。10 秒是保护下限，不是到点强制换号。
- 队列仍受 `sticky_session_max_waiting` 限制；队列已满返回容量错误，等待超时或客户端取消会清理等待状态。这些情况不把会话改绑到其他账号。
- 账号停用、配额耗尽、实际 RPM 到顶、模型或权限不符、明确冷却、质量与利润等准入限制继续生效；近期错误率过高仍可触发健康逃逸。需要换号时沿用现有故障转移规则。

覆盖 OpenAI 高级和普通调度、Responses 续接，以及通用 Messages/Chat/Responses 的黏性容量等待。模型路由、任务归属和协议能力约束保持有效。

## 持续流量的短期预留

身份来自明确的线程、会话、`prompt_cache_key` 或 Claude metadata 会话字段，按 API Key、分组、平台和执行分支隔离并哈希后记录。仅有 `stream: true` 或相同首条消息不会获得预留。

| 流量 | 进入预留的条件 |
| --- | --- |
| 带明确身份的 HTTP 会话 | 同一账号上至少两次实际取得并发槽，首尾间隔至少 10 秒，且此前的活动记录未过期 |
| Responses WebSocket | 使用持续连接的会话身份；无明确身份时使用本连接独立标识 |
| 无明确身份的一次性请求、token 计数和非文本入口 | 不建立预留 |

稳定会话完成一轮后保留 **60 秒**的空闲容量提示。同一会话有多个在途请求时，要等全部释放后才计一份空闲预留；运行中的会话只计算真实并发。下一轮进入后撤去该会话的空闲预留，闲置超时自动清除。

新请求的容量评分包含“真实并发＋空闲会话预留”。每个账号最多预留并发上限的一半、最多 64 份；并发上限为 0 或 1 的账号不预留。优先调度的容量档和分流权重、普通调度的负载排序均使用这个提示。

预留不占用真实槽位。其他可用账号不足时仍可借用这些空位，不会因预留制造无谓排队；因此它是分流偏好，不能保证下一轮一定无需等待。真实并发上限始终由原有原子准入执行。

## 状态与观测

- 预留存储在共享 Redis，同一 Redis 下的进程共享观察结果。每账号最多记录 512 个会话和 512 个在途成员，键和成员均有过期时间，不扫描全库。
- 排队轮询、抢槽失败、重复释放不会增加稳定会话数。观测超时或记录容量不足时减少或放弃预留；不会放宽真实并发准入。
- 观测采用 Redis 时间，单次辅助操作最多等待 150 毫秒。长请求超出观测有效期且未能观察结束时丢弃该观察，不凭过期记录创建空闲预留。
- 区域部署继续由 SQL 管理真实槽位；预留只共享到使用同一辅助 Redis 的区域范围，不提供跨区域独占名额。
- 账号并发统计保持真实在途数。优先调度候选 API 的 `load_percent` 仍表示真实占用，新增 `reserved_concurrency` 和 `routing_load_percent` 解释预留及调度使用的负载。

本功能不改数据库结构。升级后随真实请求积累状态，回退应用时旧版本忽略这些短期 Redis 键。
