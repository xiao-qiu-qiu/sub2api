# 实验性账号轮休

在「系统设置 → 网关 → 调度 → 实验性账号轮休」开启。自动轮休默认关闭，工作窗口 300 分钟，静置 10–30 分钟，错峰弹性 ±10%。「自动轮休时，新请求等待原账号」默认开启，旧配置缺少此字段时也按开启处理。

账号真正接到请求、并发从零变为正数时开始计时。工作期间连续超过 5 分钟没有请求，下次接单重新开始一个完整工作窗口。这里算经过的时间，不累加每个请求的执行时长。

到达计划时间后，默认采用与手动静置相同的策略：拦住该账号的所有后续请求，包括已有黏性续请求；原连接、原账号等待，在途请求继续完成。并发归零后开始静置，到期后逐步放行等待请求。

关闭「自动轮休时，新请求等待原账号」后，普通到期轮休使用原排空策略：

- **激进模式**：所有后续请求重新选号，包括已有黏性会话的新请求；当前正在执行的请求继续完成。
- **温和模式**：只允许已有黏性会话续跑，新会话换号；可能因持续续请求而延后静置。

排空期间，普通请求与 Live 租约的总并发归零后，立即开始随机静置。关闭等待开关时，静置期间旧黏性也不能进入，会由原调度逻辑重新选号。该开关不改变手动及提前静置的同账号等待行为。人工停用、质量运维停调、限流和分组规则继续生效；轮休不会修改账号的 `schedulable`。

账号列表的状态栏显示当前阶段、等待请求数、静置剩余时间，以及工作期间距离下次计划轮休的倒计时，区分手动、提前和普通自动静置。「上次手动」「上次自动」记录最近一次真正开始静置的时间；自动记录包含提前静置，排空前取消不产生记录。悬停查看完整时间。

历史在工作窗口重置、配置修改及关闭自动轮休后保留，每个账号在 Redis 中保存最近两类记录，不设过期时间；清空对应 Redis 状态后显示「暂无记录」。倒计时每秒更新，正在观察、排空、静置或逐步恢复的可见账号每 5 秒刷新状态，其他有轮休状态的可见账号每 30 秒校准工作窗口，不依赖整表自动刷新；页面隐藏时暂停查询。

## 手动静置与提前静置

在账号行右侧「更多 → 手动静置」中填写秒数并确认，默认 60 秒，可设为整数 1–7200 秒。无需开启自动轮休。确认后立即拦住分配给该账号的新请求，包括黏性续请求；请求保持原连接、原账号等待，当前在途请求继续完成。**最后一条在途请求结束后才开始静置计时**，等待队列不算账号并发，也不会延长静置。

例如 12:00 确认静置 1 分钟，最后一条请求在 12:03 结束，则 12:04 开始放行。恢复时先放行一条，之后每隔随机 **0.5–2 秒**再放行一条，直到积压队列清空；无需等待上一条执行结束，账号并发上限仍然有效。恢复期间的新请求也按同一节奏进入，客户端断开会退出等待。客户端或反向代理的超时仍然有效，静置期间不返回模型首字。

「实验性账号轮休」中的恢复间隔下限、上限按秒填写，支持小数；两者相同即为固定间隔。无需开启自动轮休也能调整，采用同账号等待的自动轮休、手动静置、提前静置和手动结束静置后的积压请求均适用。间隔按账号在 Redis 中统一控制，多实例共享；队列清空且最后一个间隔结束后恢复正常接单。没有积压请求时正常恢复。

同一菜单可「结束手动静置」。提前结束保留原工作计时，不将未完成的静置算成新周期。已经处于自动排空或静置的账号不能用手动操作缩短现有休息。

在轮休设置中开启「低并发提前静置」，可设置提前观察窗口（分钟）、并发阈值和静置时长（秒），默认分别为 **20 分钟、低于 2、120 秒**。普通请求与 Live 的总并发必须严格小于阈值，例如填 2 时仅 0 或 1 触发。进入观察窗口后满足条件即拦住后续请求，最后一条在途请求结束后按配置静置。完成后，下次真实接单启动新工作窗口；未触发则继续按原到期策略轮休。此开关默认关闭，随自动轮休总开关生效。

提前观察跟随错峰规划后的排空时刻。例如计划在 5 小时 10 分钟排空，则从 4 小时 50 分钟开始观察。准入、释放和续租都会推进状态；持续运行的普通请求约每 20 秒续租一次。

## 错峰方式

同平台、同分组归属的账号共享一个规划池。每次启动工作窗口时，在设定时长的弹性范围内评估候选时刻，依次优先选择预计静置重叠峰值较小、重叠总时长较短、接近目标时长的位置。静置时长在该轮规划时抽取，排空完成后执行。

默认 300 分钟、±10%，意味着计划排空可落在接单后的 270–330 分钟。设为 0% 则严格按设定工作时长排空。算法使用有界扫描，不保证全局最优；长请求、自然空闲、不同模型的账号资格和账号增减都会影响实际同时可用数量。启用同账号等待时，即使其他账号空闲，已等待的请求也会留在原账号。关闭等待时，普通到期轮休由其他可用账号或故障转移路径承接，没有合格账号时返回暂时不可用。

## 配置与运行

管理设置的 `account_rotation_settings` 接受以下字段：

| 字段 | 默认值 | 范围 |
| --- | --- | --- |
| `enabled` | `false` | 开关 |
| `scheduled_hold_enabled` | `true` | 普通到期轮休是否让后续请求等待原账号；关闭后使用 `mode` |
| `mode` | `aggressive` | `aggressive` / `sticky` |
| `work_minutes` | `300` | 整数 1–1440 |
| `rest_min_minutes` | `10` | 整数 1–120 |
| `rest_max_minutes` | `30` | 不小于下限，最大 120 |
| `stagger_percent` | `10` | 整数 0–30 |
| `early_rest_enabled` | `false` | 提前静置开关 |
| `early_rest_window_minutes` | `20` | 整数 1–1440，观察起点不早于工作窗口开始 |
| `early_rest_concurrency_threshold` | `2` | 整数 1–10000，总并发严格低于此值触发 |
| `early_rest_seconds` | `120` | 整数 1–7200 |
| `recovery_min_interval_ms` | `500` | 整数 1–60000，界面按秒填写 |
| `recovery_max_interval_ms` | `2000` | 不小于下限，最大 60000 |

`revision` 由服务端维护。修改策略会重置普通旧周期；已经开始的同账号等待静置（普通自动、手动或提前）会完成后再按新配置运行，关闭等待开关或自动轮休也不会中断本轮静置。逐步恢复中的已确定放行时刻保留，后续间隔采用新配置。旧配置缺少新增字段时使用默认值。其他服务实例最多约 30 秒刷新配置。Redis 保存状态并提供统一时钟，检查、占槽和最后一个请求释放都采用原子操作。长请求持续续租并发槽，避免仍在生成时被判定为空闲；自动轮休关闭时仍跟踪真实并发，以支持随时手动静置。Redis 状态丢失后，计时会重新建立。

手动操作接口：`POST /api/v1/admin/accounts/:id/rotation/rest`，请求体为 `{"seconds":60}`；空请求体或 `{}` 默认 60 秒。兼容旧客户端的 `{"minutes":1}`（整数 1–120），不能同时提供两种单位。`DELETE` 同一路径结束手动静置，`GET` 查询当前状态。返回 `data.account_rotation`，包含 `automatic_enabled`、`last_manual_rest_at`、`last_automatic_rest_at` 和 `last_automatic_rest_reason`；时间为 Unix 秒，0 表示尚无记录。重复开始正在执行的手动静置不会延长倒计时。

适用于网关调度的账号与上游，HTTP、WebSocket 每轮、Live 和网关辅助请求均参与准入；未经过网关调度的管理员主动测试、后台账号维护任务独立运行。启用等待的自动轮休、手动及提前静置会等待同账号恢复；关闭等待后，普通到期轮休要求换号时，已建立且不能迁移上游会话的 WebSocket 会在下一轮返回关闭码 `1013`，客户端需携带完整上下文重连。绑定账号的远程缓存资源也不能透明转移，普通到期轮休需要换号时返回暂时不可用。

同账号等待作用于已经进入 Sub2API 的请求。上层网关的渠道切换策略独立运行；只读容量接口仍按即时容量报告状态，全部合格账号正在静置或恢复节流时返回 `busy`，不将可排队误报成有空闲容量。

当前使用 Redis 并发权威；配置了 regional SQL 并发的实例会拒绝启用自动轮休及手动静置。
