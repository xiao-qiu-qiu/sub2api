# BPS 糖果题检测

## 添加账号与预设

在「账号管理 → 添加账号」选择 OpenAI，打开「添加后启用 BPS」，选择 WS/SSE 和 BPS 模型。普通 OAuth / 2FA 会在独立 Excel 授权完成后启用；Excel OAuth 使用本次登录授权。

并发、优先级、负载、倍率、分组、代理、模型映射及 BPS/Codex 选项配置好后，点击「保存为预设」。下次添加时手动「读取预设」，仍可继续调整；修改后再次保存即可更新服务端的管理员共用预设。预设不保存账号身份和凭据，也不改已有账号。读取后保留当前表单配置，全局初始质量规则和 2FA 准入继续生效。

## 快捷创建与运行

1. 打开「质量运维」，点击顶部「BPS 糖果题」。表单已填入糖果题、参考答案 21 和 BPS 观察通道，不会立即创建或执行。
2. 选择账号，或使用「所有匹配账户」创建持续覆盖新账号的规则模板。测试模型默认使用 gpt-6-astra，可改为账号 BPS 名单中的模型；配置模型映射时可填写映射入口。多个账号名单不同时分别建规则。
3. 默认使用“直接比对答案”，无需选择判题分组或模型；需要语义判断时再切换模型判题。选择检测间隔并保存。点击顶部对应探针查看它的账号和运营记录，右键或齿轮打开配置。单账号规则仍可点击「立即检测」。

普通「新建规则」仍可选择糖果题和账号当前路由；原生状态探针继续独立可选。选择 BPS 会锁定仅观察，关闭恢复逻辑；测试沿用账号已有的 WS/SSE 选择。

- 只检测该账号已配置走 BPS 的模型。账号未开启 BPS、授权仍为 pending、模型不在其 BPS 范围内或网关不可用时，记录不可检测；不会改走原生通道，也不会为测试开启 BPS。
- 答对、答错和请求失败都只记录检测结果。该模式不启停 BPS、不移分组、不改调度，也不自动恢复旧设置。检测请求收到 401/403 时不会触发业务请求的账号停用、BPS 自动关闭或移组动作；正常业务请求仍遵循原有策略。
- 手动独立规则按账号和类别保留一条，暂停仍占名额。分组模板按模板身份独立建立任务，不与其他模板争抢同类名额；零任务及同步异常会明确显示。详见[独立探针与本地判题](quality-probe-workspace.md)。

## 从旧规则批量转换

勾选规则后进入批量编辑，勾选「检测配置」并从状态探针改为糖果题。选中的规则中包含自动 BPS 规则时，表单默认切到 BPS 检测通道，同时勾选关联的处理和恢复字段，并显示转换说明。填写判题配置后保存。

转换会把本次选中的规则改为只记录结果，清除其中的自动启停配置和旧处置归属；账号当前的 BPS 开关、模型范围、分组和调度设置保持原值。已经开始的旧检测不能在转换后恢复账号设置。其他规则不受转换影响。

批量保存仍为逐条执行，失败项按规则编号显示，重试只处理失败项。

## 配置与升级

- 使用既有计划接口，配置为 `pelican_config.question_kind=candy`、`test_channel=bps` 和 `quality.action=observe_only`。后端将自动恢复关闭，并移除 BPS 启停及目标分组配置。
- `test_channel` 缺省或为 `account` 时保留原有账号路由行为。旧自动 BPS 规则继续用原生状态探针；本改动不会批量迁移它们。
- 迁移 `258_quality_observation_scope.sql` 扩展规则类别唯一索引，让仅检测规则与另外两类规则共存。它不修改账号数据；通过应用现有迁移流程执行，前后端应一起升级。
